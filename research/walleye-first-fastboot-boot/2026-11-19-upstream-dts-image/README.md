# The image of the exact upstream board dts (2026-11-19)

This folder holds what builds `boot-upstream-dts.img`: z21 with its dtb replaced by one built from the series' `msm8998-google-walleye.dts`
(`../2026-11-19-upstream-dts/`, two patches on Linux v7.3), for one attended-free boot (item walleye-try-upstream-dts). Built, not tried: no phone touched.
`build/build-upstream-dts-image.sh Z21_BOOT_IMG KERNEL_TREE OUT_DIR` makes it; the checks (31 of them) stop the build on a failure.

## What is in the image

- The kernel (Image.gz), the ramdisk (z14's network shell), the header, the command line and the AVB footer are **z21's, byte for byte**; only the dtb differs.
- The dtb is the series' dts, **unedited** (the script checks the tree holds both patches exactly, with `git apply -R --check`), through two wrappers that are not part of the series:
  - `msm8998-google-walleye-series-base.dts`: includes the series' file and deletes two nodes of msm8998.dtsi, `pcie0` and `blsp1_i2c5`.
  - `msm8998-google-walleye-series.dts`: the base plus `msm8998-google-walleye-series-stubs.dtsi`, 126 empty stub nodes generated by `build/gen-overlay-stubs.sh` from the base's dtb
    (the script regenerates them and compares with the committed file).
  - built with `-@`; the stub label `clock_gcc` is then pointed at the real gcc with `fdtput`, as every image since z3.

## What the series' dts lacks for this phone's bootloader (findings for the series' cover letter, none an upstream fault)

1. **The overlay merge needs stubs.** The series' dtb with symbols: `fdtoverlay` of the phone's dtbo entry 3 fails with `FDT_ERR_NOTFOUND` (137 labels the overlay targets, the board defines 11).
   An upstream board file cannot carry those; the stock bootloader's merge is not upstream's concern.
2. **The overlay overwrites two disabled nodes of msm8998.dtsi by name**: `pcie@1c00000` (reg, ranges) and `i2c@c179000` (compatible, interrupts, clocks, clock-names, dmas, pinctrl, status): 11 collisions on 2 nodes, measured once on the series with the stubs added and nothing deleted (not a check of the script: the series alone does not merge at all).
   Both are off in the series; the wrapper deletes them, as the lab's dts does (decision 2026-11-19-walleye-overlay-collisions-as-a-class). Not needed upstream.
3. **Nothing missing to reach USB**: the series has `gpio-reserved-ranges = <0 4>, <81 4>` on tlmm, the UFS nodes off, the debug uart on, ramoops at 0xa1100000.
4. No touch node, no pwm, no APSS watchdog (the series has none): no touch is expected on this image.
